## Fetcher relocation details

The following paths are relative to the reviewed `nrao-archive-fetcher` repository.

- `workflows/radioastro_calibrators/run_manifest.py`: derives `downloads/` and `extracted/` from the resolved manifest parent. An environment-root change alone does not redirect a command still given the old manifest path. Entries already marked `extracted` are skipped without checking their recorded paths.
- `src/nrao_archive_fetcher/download.py`: `DOWNLOADED_STATUSES` includes `downloaded`, `extracting`, `extracted`, and `extraction_error`. Ordinary reruns do not redownload extracted entries. New request synchronization can reset an `extraction_error` when a different link arrives; preserve rejected-state provenance.
- `src/nrao_archive_fetcher/sync.py`: `merge_shards()` globs all sibling `manifest.shard-*-of-*.json`, ordered by mtime, and copies processing fields when download commands match. `write_shard()` also preserves previous shard processing fields. Editing only the main manifest is insufficient: a later submission can restore obsolete paths. Reconcile progress with no active writers, archive old shard files outside the active directory, migrate the authoritative state, then generate fresh shards.
- `slurm/submit_shards.sh`: always merges shards before request sync/submission. The automatic incoming-path rule recognizes `.../local/runs/<group>/`; the new root does not match it. Set `INCOMING` explicitly to the separate reports/incoming request copy. Its active-job check is useful but does not inspect arbitrary non-Slurm processes or every possible cluster; the runner still owns the quiet window.
- `slurm/env.sh`: **tracked**, although another script's comment says otherwise. It currently defaults to `$RADIOASTRO_STORAGE/nrao-archive-fetcher`, not the requested `$RADIOASTRO_STORAGE/data/nrao-archive-fetcher`. Correct the root and dependent `NRAO_RUNS_ROOT`/`NRAO_LOG_DIR` together. Do not confuse it with radioastro's `RADIOASTRO_SCRATCH`, whose setup links `collect/extracted` into `data/extracted`.
- `workflows/radioastro_calibrators/extract_entry.py`: uses `split(datacolumn='corrected', keepflags=True)` and records the **input** selected SPW. A single selected data column is written to output `DATA`, which matches radioastro's explicit `DefaultImagingConfig.datacolumn='data'`. No change to that default is needed. This output-column behavior is documented in [CASA split](https://casadocs.readthedocs.io/en/v6.7.5/_modules/casatasks/manipulation/split.html).
- `run_manifest.py` only applies `delete_original` immediately after a newly successful extraction. Restarting with that flag does not clean raw products for entries already extracted. Perform reviewed cleanup separately and update `download_root`/`original_download_deleted` consistently.
- Sidecars contain historical absolute paths as well as measurements. Preserve original provenance; migrate active manifest paths deliberately. The proposed metadata audit should read sidecars at their new actual locations, not blindly follow every historical embedded path.

## Thermal path and compatibility details

[`compare_extracted_thermal_simulations.py`](../scripts/compare_extracted_thermal_simulations.py) confirms `main(experiment_dir=None, *, sample_ids=None)`. It discovers `<id>/<id>/<id>.ms` under `collect/extracted`, resolves the candidate, and compares the resolved stem to requested IDs. A link resolving to a long fetcher basename fails; a root-directory storage symlink with canonical leaf names is compatible.

The current thermal report puts successful entries in `samples` and failures in `failures`. In addition to the simulation MS and metadata, v2 preparation needs original QA/model flux, result directories, imsize, source SNR and predicted RMS. A failed entry with partial output is skipped on resume. The runbook therefore requires a complete schema/product audit and explicit retry handling before the report is frozen.

Local old thermal settings match current imsize `[256, 256]`, seed `20260907`, sampler `8bit`, eta `0.93`, metric-region policy and SNR basis. The current driver additionally records `fits_invalid_policy='fill'`, while the inspected legacy report lacks that field. Absence is **unknown**, not an equal-value proof: compare the old producing code/effective behavior and document the result before claiming full numerical equivalence. CHPC CASA/runtime versions also remain to be checked.
