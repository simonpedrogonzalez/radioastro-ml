# PB-clipping comparison: minimal implementation plan

Status: implemented and tested on the two MSs below; dataset v1 remains unchanged.

1. **Add one opt-in parameter.** Add `pblimit: float | None = None` to the direct `image_ms(...)` function. With `None`, omit the `tclean` keyword so existing imaging runs exactly as before. With `-0.1`, pass `pblimit=-0.1` to its final dirty and CLEAN `tclean` calls; leave the first-pass grid sizing and `image_ms_VLA_pipe` untouched. Record the chosen value in QA. Negative `pblimit` removes CASA's internal PB T/F image mask; it does not promise to recover pixels already set to zero by normalization. Do not use `-1`, `0`, or `1`. [CASA documentation](https://casadocs.readthedocs.io/en/stable/api/tt/casatasks.imaging.tclean.html#pblimit).

2. **Make one test script.** Add `scripts/test_pb_clipping.py`. Use the existing thermal-run MSs `0029+349_matched_snr.ms` (circular-support example) and `0005+383_matched_snr.ms` (square-support control), both under `collect/experiments/extracted_thermal_simulation_comparison_20260909T005739/<source>/simulation/`. For each MS, call `image_ms` twice with all other settings identical: once with the parameter omitted (current PB clipping), once with `pblimit=-0.1` (mask removed). Match dataset v1's FITS-fill setting and retain intermediate CASA images for a pre-fill support check. Write the four runs under fresh, separate output directories; never overwrite the old images or dataset. Retain each run's dirty, CLEAN, residual and PSF FITS.

3. **Generate one HTML report.** Have the script use `scripts.reporting` to render `report.html`. Make one section per source, with two rows (**current** / **`pblimit=-0.1`**) and four columns (**dirty / CLEAN / residual / PSF**): **16 image panels total**. Use the same color limits for each before/after product pair so differences are visible. Use the existing imaging plot style for the three Jy/beam products; label the PSF's color scale as dimensionless. Include brief run labels and native-valid/FITS-zero pixel counts so the visual result can be interpreted. Return the full path to the HTML for review.

Afterward, check that both default runs match the old support and imaging parameters, especially that the previously square source remains square and numerically unchanged within normal CASA rerun tolerance. For the circular source, check whether the formerly clipped area contains real finite values in dirty/CLEAN/residual, rather than only a removed mask or FITS zero fill. Also check that all four products retain the same shape, WCS, cell size and beam geometry. Stop after the comparison report; do not rebuild the dataset until the report has been reviewed.

Result: [HTML comparison](../collect/experiments/pb_clipping_comparison_20260928/report.html). All 16 panels are embedded. The square source's four FITS products are identical between settings; the circular source's 23,767 formerly masked/zero pixels are populated in dirty, CLEAN and residual with `pblimit=-0.1`, while values inside the old valid region and the PSF are identical. The default reruns' QA metrics and imaging parameters match the original thermal-run QA. No dataset regeneration has been done.
