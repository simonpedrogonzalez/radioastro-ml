## 1. Scientific contract

For each parent observation, retain its point-source position/shape, visibility sampling and nominal component noise scale, but set Stokes-I flux to the original CASA CLEAN model sum above, without SNR-preserving downscaling. Select one eligible antenna per parameter vector, uniformly from antennas with positive valid visibility contribution. Amp and phase act on that same antenna, with complex gain `g = A exp(i phi_rad)`. Store degrees in the case specification and convert to radians exactly once before calling the gain functions. Other antennas have unity gain. Keep this antenna fixed for every paired removal and repeated noise seed. Different-antenna mixtures are a later extension, not an implicit change.

Define the simulated visibility on baseline `ij` as

```
Y_ij(A, phi, a, seed) = g_i conjugate(g_j) V_ij + a n_ij(seed)
```

`V` is noiseless true-sky visibility and `n(seed)` is one nominal thermal-noise realization. Gains act on `V`, never on the added noise. `a >= 1` is TOTAL noise STD / nominal STD. This follows the new pilot's paired scaling convention, not Dataset 1's independent extra-noise norm convention. Keep the same `n` in every counterfactual. Record this coupling because finite-realization damage depends on it.

Use the **standard `scripts.imaging.image_ms` pipeline and its existing `DefaultImagingConfig`**, via the recovery helper. Do not add a direct `tclean` path or custom stopping settings. Preserve the pilot's adaptive stopping policy (`dirty_peak_fraction=1e-7`, `nsigma=3` in its saved configuration), recording the resolved settings per case. Do not freeze a numerical threshold measured on a different image. Use the existing recovery workflow's noiseless reference to fix grid, WCS, restoring beam, valid evaluation support `Omega`, CLEAN search mask and annulus per source, with unchanged flags, selection and nominal weights. A configuration/version mismatch with the pilot must be visible before execution. Noiseless references are infrastructure, not ordinary training cases. Damage measures removal under this standard imaging policy, including its adaptive response.

For every reconstructed raw CLEAN model `M` (Jy/pixel), convolve directly with the fixed **peak-one**, rotated restoring Gaussian, with zero padding. Let `C` be this model and `T` the true sky at the same resolution, both in Jy/beam:

```
y_all = sqrt(sum_Omega((C - T)^2) / sum_Omega(T^2))
d_k   = y_all - y_without_k
b     = [A != 1, phi != 0, a > 1]          # amp, phase, noise
```

Removal sets only `A=1`, `phi=0` or `a=1`. All other physical parameters and random draws remain unchanged, and both images use the same standard imaging policy and reference geometry. For mixtures, never substitute the ordinary control for `y_without_k`. Signed damage can be negative. Do not require `sum(d) = y_all - y_control`, since interactions invalidate that identity. Presence describes the injected mechanism, not whether its measured damage is positive or detectable. Ordinary controls have `b=d=0`, but their `y_all` is measured and generally positive. Empty fitted models have `y_all=1`, not an invalid label. Nonfinite outputs, missing products and infrastructure failures are invalid cases, not zeros. Record convergence failures and finite iteration-limit outcomes separately. Check `y>=0` and `d_k<=y_all` within numerical tolerance. Compute convolution on the full model grid before restricting to `Omega`, checking finite values and valid support rather than treating masked pixels as measurements.

## 6. Losses and output contract

Output order is **`[d_amp,d_phase,d_noise,y_all,logit_amp,logit_phase,logit_noise]`**. Damage and total-error heads are linear. Apply three independent sigmoids only to presence logits. No softmax, damage clipping, probability gating or forced additivity. Total error is physically nonnegative, but retain/report any negative linear predictions rather than hiding errors with clipping. A constrained link can be a later explicit ablation.

Scientific reporting retains the raw losses:

```
L_d   = sum_nk w_nk * (pred_d_nk - d_nk)^2 / (N*3)
L_y   = sum_n  (pred_y_n - y_n)^2 / N
L_b   = sum_nk BCEWithLogits(logit_nk, b_nk) / (N*3)
```

Use stable logits BCE. Aggregate numerators and counts across minibatches before division. Unknown targets must be masked before subtraction. Do not normalize damage by observed-label count or total inverse-probability weight.

To prevent a repeat of target-scale domination, fit regression outputs in **training-only RMS units**, without centering: `s_k=max(1e-3,sqrt(sum_n w_nk*d_nk^2/N))` and `s_y=max(1e-3,sqrt(mean(y^2)))`. The floor is a declared numerical scale, not a damage tolerance. Freeze scales from each fitting partition, including each OOF fold. Store and invert them for all reported predictions. Their sparse estimates can be noisy, so report them. Require observed active damage labels for each class in every fitting partition. For validation/test `J`, always use the fitted model's training scales, never recompute scales on the evaluated split. Initialize each fold/model independently.

Optimize/select `J = L_d_scaled + L_y_scaled + L_b`, with equal task weights initially. This deliberately changes optimization priorities relative to raw V3 MSE and must be labeled as such. Keep raw per-task/per-output scores visible. Do not claim a lower `J` means improvement on every task. Report a fixed-unit-scale ablation if evaluating whether scaling helps, without adding an automatic weight search.

## 7. Same five model families

| Family | Minimal change |
| --- | --- |
| MLP | Train-only input standardization, `p -> 64 ReLU -> 64 ReLU -> 7`, shared trunk, above loss |
| Shared XGBoost | `hist`, `multi_output_tree`, seven raw outputs, custom mixed squared/logistic objective |
| Independent XGBoost | Four scalar regressors and three scalar binary classifiers, same targets/masks/scales |
| XGBoost + XGBoost | Shared seven-output binder on `X + independent predictions + shared predictions` |
| XGBoost + MLP | Same binder inputs and shared MLP loss |

Both binders have **22 inputs** for combined8: 8 features plus two blocks of 7 predictions. Blocks contain three decoded physical damage predictions, decoded `y_all` and three probabilities. Never feed labels, observation masks or injected presence into a binder. Use source-held-out OOF predictions for every training row and full-training first-stage fits for validation/test. Decode fold-local target scales before combining blocks. Both binders share identical saved OOF matrices. Independent models retain absent-type zeros and use fractional damage weights, not boolean filtering.

The XGBoost objective is a small reusable function, not seven fake squared-error targets. For the summed objective `N*J`, in scaled regression units:

```
damage: grad = (2/3) * w * (z - target), hess = (2/3) * w
y_all:  grad = 2 * (z - target),         hess = 2
presence: p = sigmoid(z)
          grad = (p - b)/3, hess = max(p*(1-p), 1e-6)/3
```

Use zero Hessian/gradient for unobserved damage entries, without flooring them. Logistic Hessian flooring is solely numerical stabilization. Use the same constants in independent fits (custom scalar objectives or equivalent sample weights) so scalar loss normalization is consistent. This does not make scalar and vector trees equally regularized: shared trees jointly score splits and regularize more leaf values, so retain the explicit small tuning grid for each family. Do not divide derivatives by dataset size while retaining unchanged regularization. Set `num_target=7`, explicit raw `base_score=0`, disable the inappropriate built-in metric, and evaluate `J` explicitly on raw margins with the correct transforms. When using built-in scalar binary classifiers, specify their probability-space intercept correctly (`0.5` corresponds to raw margin zero), rather than copying raw `base_score=0` into `binary:logistic`. No off-diagonal Hessian is needed for this separable loss, while tree splits are still shared across tasks.

The installed XGBoost **3.4.1** successfully ran a synthetic seven-output `multi_output_tree` mixed-objective smoke with missing damage weights during this design review. Pin/record the actual environment and require that smoke in tests. Multi-output remains an experimental interface, so do not assume every scalar-tree option works. See the official [multi-output documentation](https://xgboost.readthedocs.io/en/stable/tutorials/multioutput.html) and [custom-objective example](https://xgboost.readthedocs.io/en/stable/python/examples/multioutput_regression.html).

Reuse the existing small tree grid and MLP defaults. Select first-stage settings on validation `J`, freeze them, generate three source-grouped OOF blocks, then select binders on validation `J`. This is the current development-selection pattern, not nested CV and not an unbiased validation estimate. MLP early stopping also uses validation `J`. Keep all preprocessing fold-local. Save selected train-fitted models without refitting on validation initially. A separate explicit test-evaluation command loads only frozen models/configuration, after selection, and reports test once. Do not expose test curves during development.

## 8. Evaluation and minimum implementation surface

One report should show all three tasks side by side, plus raw/scaled losses and selection settings. Include zero and training-constant regression baselines and training-prevalence classification probabilities. Report damage/y MAE, RMSE and R², and **damage error separately on active rows (b_k=1) and absent rows (b_k=0)** for every model and baseline. Absent rows have exact zero damage, so pooled damage scores are partly driven by those easy zeros; the separate table shows whether a model is accurate on injected errors or only near zero on absent ones. Active-row estimates use `sum_active w*err²/|active|`; absent rows are fully observed. Saved as `damage_active`/`damage_absent` in `results.json` metrics and `L_dk_active`/`L_dk_absent` in losses. A hurdle (presence × conditional damage) model is deferred. Also report multilabel per-class precision/recall/F1 at fixed 0.5, average precision, BCE and Brier score. Mark undefined metrics when a slice lacks positives/negatives or target variance. Balanced synthetic-mask probabilities are not calibrated deployment probabilities without a deployment distribution.

Show per-output zoomed diagonals with common train/validation axes, y/d distributions, absence errors, and slices by mixture, nominal source SNR and injection branch. Use source-group bootstrap intervals, keeping all seeds and variants of a source together. Identify these as empirical intervals conditional on the realized label-selection design, not a complete uncertainty calculation for unseen counterfactuals. Because damage labels are sparse in **all** splits, report only observed damage points and inverse-probability-weighted loss/MAE/MSE in each split. Per-output RMSE is the square root of its weighted MSE. For a fixed subset `S` defined from known metadata (all rows or active rows), estimate MAE/MSE with `sum_S w*abs(pred-d) / |S|` or `sum_S w*(pred-d)² / |S|`. The denominator counts all eligible rows, including unknown active labels. These are inverse-probability estimates, unbiased over removal selection for fixed predictions independent of that selection. For descriptive R², use `mu_w=sum(w*d)/sum(w)` and `1-sum(w*(pred-d)²)/sum(w*(d-mu_w)²)` on observed entries. Label R² and RMSE as nonlinear estimates, not unbiased dense scores. An absent/near-zero denominator or a slice with no observed active labels yields unavailable diagnostics, not evidence of zero damage/error. Validation selection and training fit depend on observed labels, so their selected scores do not have the fixed-prediction unbiasedness guarantee. Missing-label uncertainty remains, even with many ordinary zero labels. A missing active damage value must never appear as a zero target in a plot, count, or metric. Classification and total-error labels remain complete and need no inverse-probability weighting. Binder training scores are in-sample binder scores on OOF expert inputs. Never interpret them as end-to-end held-out performance.

Keep implementation small:

3. `ml/multitask.py`: loader, common loss/transform contract, mixed objective, current five-family fitting/OOF orchestration and artifact serialization. Reuse `COMBINED8_FEATURES`, grid, source folds and scaler/model patterns. Keep existing old experiment entrypoints intact.
4. Extend the existing report with the parameter-only preview and achieved training coverage above. Extend reusable report components for the three-task table/plots. One model report-only path reads saved predictions and recomputes metrics, without fitting. Save code/config/dependency hashes and independently verifiable scalar predictions.

Required checks before a full run: analytic convolution/empty-model cases, identity and mixed-gain visibility formula including antenna orientation, noise scaling and removal invariants, split isolation, deterministic sampling and boundary truncation, sparse-loss expectation enumerated over every possible removal for fixed predictions, normalized damage-CDF and weighted-R² edge cases, finite-difference objective derivatives, no NaN gradient propagation, OOF source exclusion and scale isolation, model save/reload equivalence, and interruption/resume/cleanup under a small byte limit. No old simulations are resumed and no production dataset is launched by this design change.

## 9. Production run (train and validation only, 2026-11-05)

- **Splits:** train (100 sources) and validation (21) only, in separate output directories under `runs/dataset-v2-20261105/`. Test stays reserved and is not simulated now. Membership comes from the fixed canonical partition lists, so source and parent-MS sets are disjoint; this is checked after planning.
- **Parallel execution:** `--workers N --worker i` gives each process a deterministic, size-balanced, disjoint source subset with its own lock file. Cases, scratch and outputs are per source, so workers do not share files.
- **Smoke reuse:** the production-budget smoke (train source 0449+113) is run in its own directory with the identical configuration. `--prepare --import-from <smoke>` copies its preparation and reference, and `--execute --import-from <smoke>` copies its committed cases, so their case IDs, settings and reference hashes match and nothing is recomputed. Imported records keep `imported_from` provenance (path, SHA-256, original plan hash).
- **Original data:** the collected MSs under `collect/extracted/` are only read. `simulate_ms` copies each into the run's scratch before predicting the noiseless model; all writes stay inside the run directory. Preparation and execution recheck each original MS's content hash, and a before/after fingerprint of `collect/` is recorded.
- **Estimates:** seconds per image ≈ 6 s + 0.085 s/MB of original MS, fitted to the pilot sources. Scratch scales with the original MS (not the larger matched-SNR simulation MS used by the earlier estimate); default `max_scratch_bytes` is 16 GB.
